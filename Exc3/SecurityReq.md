# Требования внешних интеграций

## Требования к безопасности
1. Исключение из контрактов данных персональных данных: ФИО, номера телефона, почты
2. Шифрование данных:
    - Все данные, передаваемые между системами, должны быть зашифрованы с использованием протоколов TLS/SSL
    - Данные в базах данных также должны быть зашифрованы
3. Защита от атак:
    - Реализация защиты от распространенных атак, таких как SQL-инъекции, MITM - посредством контрольных сумма и сертификатов
    - Внедрение механизмов для предотвращения DDoS-атак - Rate Limiter на входящий трафик, в случае атаки со стороны контрагента
4. Логирование и мониторинг:
    - Все запросы и ответы должны логироваться для последующего анализа.
    - Настройка мониторинга для выявления подозрительных действий или аномалий в трафике.

## Протоколы аутентификации и авторизации
- Для авторизации необходимо использовать существующий механизм SSO на базе Keycloak, при взаимодействии между сервисами JSON Web Tokens (JWT) - что исключит несанкционированный доступ
- Для аутентификации можно использовать ролевую модель как на уровне приложений, так и на уровне инфраструктуры k8s. Роль назначаются с учетом принципа минимальных привелегий.

## Описание взаимодействия
Модуль `smart-home-app` посылает управляющие сигналы на сервера сервисов умного дома. В частности открытие домофона или шлагбаума. При это учитывает роль источника, который инициирует действие. Например, кто-то из родственников может открывать только домофон.

Не отражено на схеме C4, но для отправки биометрии или номера машины необходимо заключенное соглашение между собственником и оператором умного дома. Иначе сервис недоступен.

В кейсе домофона - сервер оператора может инициировать Websocket соединение, что запускает показ видео с камеры дофомона в приложении пользователя, до момент отказа или открытия двери.
