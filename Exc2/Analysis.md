# Разработка проверочного листа по безопасности

## Анализ подсистем
Основные подсистемы:
1. Система работы с клиентами:
    - Управление информацией об объектах
    - Проведение сделок онлайн
    - Проведение онлайн/оффлайн туров
    - CRM

2. Система работы с собственниками:
    - Предоставление и оплата услуг ЖКХ
    - Предоставление услуг "Умный дом"
    - СRM

3. Система бухгалтерского учета
4. Аналитическая система
5. Выделенный сервис Single Sign On (единый подход к аутентификации)

---
Возможные уязвимости:
- Нарушен контроль данных, клиент может быть заведен через СRM, либо сервис сделок
- Передаются персональные данные в рамках контрактов с поставщиками ЖКХ
- Централизация данных для аналитики - риски утечки
- Нет системы выявления и реагирования на инциденты ИБ
- Возможно, нарушется закон при обмене данными (передаются запрещенные категории, точно персональные данные)

## Выбор разделов для проверочного листа

Таким образом необходимо включить в проверочный лист следующие разделы:
1. Управление доступом - оценить риски и качество работы существующего SSO-решения. Оценить ролевую модель и выделить сегменты сети для критических данных.
2. Безопасность данных - провести категоризацию данных, проверить использование шифрования при создании резервных копий (в том числе в облачной части), оценить качество DR-планов по безопасности и методы контроля сохранности данных.
3. Особое внимание - Защите инфраструктуры. Оценить стыки приватных и публичных облачных КТС. Также рассмотреть применимость системы класса SIEM и автоматизации работы с инцидентами ИБ. Отдельно проверить использование антивирусов и автоматическое обновление их баз.
4. Дополнительно - анализ СКУД на инфрастуктуре приватного ЦОДа, методы инвентаризации и утилизации КТС
